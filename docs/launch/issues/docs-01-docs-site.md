## Context

All documentation is Markdown in the repository: `README.md`, `CONTRIBUTING.md`, `docs/adapter-contract.md`, `docs/agent-testing.md` and the generated `ADAPTERS.md`. That is fine for contributors, but a visitor who wants the client setup, the tool list and the adapter contract has to jump between files on GitHub.

## Proposed approach

- Use MkDocs with the Material theme (or another static generator, if you explain why). Put the configuration in `mkdocs.yml` and the build dependencies in a `docs` dependency group in `pyproject.toml`, next to `dev`.
- Navigation: Home, Quick start per client, Toolsets, Adapters, Adapter contract, Testing with M3, Contributing.
- Do not copy content. Include the existing files so there is one source of truth. ADAPTERS.md must stay generated by `make adapters-md`.
- Add a workflow that builds the site with strict mode on every pull request, so a broken link fails the check, and deploys to GitHub Pages from `main`. The existing workflows pin each action to a commit SHA, and the new one should too.
- Add a `make docs` target that serves the site locally.

## Acceptance criteria

- [ ] `make docs` serves the site locally, and the pages above render with working navigation.
- [ ] `mkdocs build --strict` passes locally and in CI.
- [ ] No page duplicates text from the README or the other documents.
- [ ] The deploy job runs on `main` only and has the minimum permissions it needs.
- [ ] The README links to the published site once it exists.
- [ ] `make test` and `make lint` pass, and ADAPTERS.md is unchanged.

## Notes

Ruff formats code blocks inside Markdown files, so run `make fmt` before you commit.
